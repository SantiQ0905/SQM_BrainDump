1. OVERVIEW
================================================================================

The Budget feature is a personal cashflow tracker built into the brain-dump app.
It tracks income and expenses across multiple bank accounts and credit cards, with
support for entering transactions via the web UI or via Telegram bot messages.

Key capabilities:
- Fiscal-month cashflow: income, expenses, net flow per account and category
- Starting balance configuration per account (debit and credit cards)
- Credit card utilization tracking (limit, spent, available, cut date)
- Subscription reference list (recurring charges by billing day)
- Telegram bot shortcut: type a transaction directly from your phone
- PIN-protected setup page to configure initial balances each month
- Balance reconciliation to auto-correct gaps when starting mid-month

FISCAL MONTH
------------
The budget does NOT use calendar months. The cycle runs from the 16th of one
calendar month to the 15th of the next (e.g., "Mar" = Mar 16 – Apr 15). This
aligns with payday on the 16th.

The month header in the UI shows the full range: "Mar 16 – Apr 15, 2026".
The YYYY-MM identifier (e.g., "2026-03") refers to the fiscal month that
STARTS in that calendar month — so "2026-03" means Mar 16 – Apr 15, 2026.

Credit card cut dates (AMEX: 4th, NUCredit: 6th) fall in the middle of each
fiscal cycle (roughly 18–20 days in), not at the boundary. This is expected.

To change the fiscal start day, update FISCAL_START_DAY in both:
  src/features/budget/BudgetPage.tsx
  api/budget/index.ts

3. BUDGET SETUP PAGE (/budget/setup)
================================================================================

PURPOSE
-------
This page configures the "starting state" of each account for the current fiscal
month. It stores per-account anchor balances in `budget_monthly_savings`, which
the main budget page uses to compute running balances as transactions accumulate.

The page has TWO MODES — it auto-detects which to show based on today's date,
but you can always switch manually.

PIN PROTECTION
--------------
Access requires a PIN validated against the `BUDGET_SETUP_PIN` environment
variable. Once verified, the session is stored in sessionStorage so you do not
need to re-enter it in the same browser tab.

--------------------------------------------------------------------------------
MODE A: FRESH START — "on the 16th"
--------------------------------------------------------------------------------

Use this when setting up on or very close to the 16th (fiscal month start).

DEBIT ACCOUNTS — one field per account:
  Enter the balance in the account right before any transactions on the 16th.
  Example: you had $2,000 in NUDebit before payday hit → enter $2,000.

CREDIT CARDS — one field per account:
  Enter the amount owed from the previous billing cycle.
  If you paid the balance in full, enter 0.

How the math works after setup:
  Dashboard balance = starting balance + sum of all logged transactions
  Example: Starting $2,000 + Salary +$16,000 − Groceries -$300 = $17,700

--------------------------------------------------------------------------------
MODE B: MID-MONTH CATCH-UP — "setting up after the 16th"
--------------------------------------------------------------------------------

Use this when you're setting up days or weeks into the fiscal cycle and already
have untracked activity (expenses, income) since the 16th.

DEBIT ACCOUNTS — TWO fields per account:

  Left field  — "Balance on the 16th" (optional)
    What you had in the account on the 16th, before that day's transactions.
    Can be left blank if you don't know.

  Right field — "Right now" (optional)
    What your banking app shows at this moment.

  Behavior based on what you fill in:

  Both filled → The app saves the 16th balance as the anchor, then
                automatically creates a single "adjustment" transaction to
                bridge the gap to today's real balance. Going forward, new
                transactions log on top of the established history.
                Example: 16th=$20,000, today=$17,400 → adjustment of -$2,600
                (covers all untracked spending between the 16th and today)

  Only "right now" filled → Treats today as day zero. No history before this
                point. Simpler but loses the 16th–today period entirely.

  Only "16th balance" filled → Saves it as anchor. Use Reconcile Balance on
                /budget later to fix the current gap manually.

CREDIT CARDS — ONE field per account (mid-month mode):
  Enter the current amount owed right now (including all charges since the 16th).
  This becomes the new baseline. Future charges after today are tracked on top.
  The 16th–today charges are absorbed into this starting balance — they won't
  appear as individual transactions, but the total is accurate.

RESULT CONFIRMATION
-------------------
After saving, the page shows:
  - Which accounts had balances saved
  - Which accounts had adjustment transactions created (with the delta amount)
  - A link back to /budget

The button label changes:
  Fresh Start    → "Save Configuration"
  Mid-Month      → "Save & Reconcile"

API CALLS MADE BY THIS PAGE
----------------------------
  POST /api/budget { action: "set-initial", pin, month, balances: { [account]: number } }
  POST /api/budget { action: "reconcile", account, actualBalance, month }
    (one reconcile call per debit account where both fields were filled)

4. BUDGET MAIN PAGE (/budget)
================================================================================

The main page is divided into several sections described below.


--------------------------------------------------------------------------------
4a. MONTH NAVIGATION
--------------------------------------------------------------------------------

At the top of the page there are Previous / Next arrows to navigate between
months (format: YYYY-MM). The currently displayed month is shown in the header.
All data (transactions, savings, summary) automatically reload when you change
the month.


--------------------------------------------------------------------------------
4b. SUMMARY CARDS
--------------------------------------------------------------------------------

Four cards show the month's top-level numbers:

  INCOME      — sum of all positive transactions for the month
  EXPENSES    — sum of all negative transactions for the month
  CASH NET    — net flow for debit accounts only (NUDebit + ScotiabankDebit)
  SAVINGS     — total cash saved (starting debit balance + cash net flow)

"Savings" is important: it tells you how much actual liquid cash you have at
the end of the month across all debit accounts combined.


--------------------------------------------------------------------------------
4c. ACCOUNT BALANCES
--------------------------------------------------------------------------------

Below the summary cards, each account shows a breakdown row:

  Account Name | Starting Balance | + Income | - Expenses | = Net Balance

  - Debit accounts show real cash flow (income added, expenses subtracted)
  - Credit cards show utilization (charges added, payments subtracted)
  - "Starting Balance" comes from budget_monthly_savings (set via Setup page)
  - "Net Balance" = starting balance + all transactions for that account

You can also directly edit the starting balance for any account inline on this
page (click the edit icon next to the starting balance number). This saves to
budget_monthly_savings via POST /api/budget { action: "set-savings" }.


--------------------------------------------------------------------------------
4d. CREDIT CARD TRACKING
--------------------------------------------------------------------------------

Credit cards (AMEX and NUCredit) get an extra section showing:

  Limit          — configured card limit (hardcoded in api/budget/index.ts)
  Already Owed   — starting balance (from Setup page)
  Spent          — total charges made to this card this month
  Available      — limit - already owed - spent
  Cut Date       — the billing cycle end date (configured per card)
  Days Until Cut — how many days until the next statement cut

Credit card limits and cut dates are configured in the API handler file
(api/budget/index.ts) in the CREDIT_CARDS constant:

  AMEX:
    limit: (see file)
    cutDay: (day of month the statement cuts)

  NUCredit:
    limit: (see file)
    cutDay: (day of month the statement cuts)

To change limits or cut dates, edit the CREDIT_CARDS constant in that file
and redeploy.


--------------------------------------------------------------------------------
4e. TRANSACTIONS LIST
--------------------------------------------------------------------------------

All transactions for the selected month are listed in a table with columns:

  Date | Description | Category | Account | Amount | (delete button)

Transactions are sorted by date descending (newest first).

Source column or indicator shows whether the transaction was entered via:
  - "web"      — added through the browser form
  - "telegram" — added via the Telegram bot

The delete button (trash icon) calls POST /api/budget { action: "delete", id }
and removes the transaction immediately.

There is also a "Reset Month" button (usually at the bottom or in a settings
area) that deletes ALL transactions and savings for the current month. This is
destructive and should only be used if you want to start the month over.


--------------------------------------------------------------------------------
4f. ADD TRANSACTION FORM
--------------------------------------------------------------------------------

A form at the top or side of the page lets you manually add a transaction.

Fields:
  Amount      — positive number for income, negative for expense (e.g., -300 or 500)
  Category    — free text or dropdown (e.g., food, transport, earnings, rent)
  Description — optional note about the transaction
  Account     — dropdown: AMEX, NUCredit, NUDebit, ScotiabankDebit
  Date        — defaults to today, can be changed

On submit: POST /api/budget { action: "add-transaction", amount, category,
                               description, account, date, source: "web" }

The list refreshes automatically after adding.


--------------------------------------------------------------------------------
4g. BALANCE RECONCILIATION
--------------------------------------------------------------------------------

PURPOSE
-------
When you start tracking mid-month, or when untracked transactions have
accumulated, the app's calculated balance will differ from your real bank
balance. Instead of hunting down every missing transaction, the Reconciliation
tool lets you enter the actual current balance and automatically creates a
single "adjustment" transaction to cover the gap.

HOW IT WORKS
------------
1. Select the account you want to reconcile (any of the four accounts)
2. Type your actual current balance (what your bank app shows right now)
3. The app computes:
     Calculated balance = starting balance + sum of all logged transactions
     Adjustment = actual - calculated
4. A live preview shows the adjustment amount before you commit
5. Click "Reconcile" — an adjustment transaction is inserted:
     Category: adjustment
     Description: Balance reconciliation
     Amount: the delta (positive if app was under-counting, negative if over)
6. The transaction list and all summary cards update immediately

WHAT THE ADJUSTMENT ENTRY LOOKS LIKE
-------------------------------------
It appears in the transaction list like any other entry:
  Date:        today (in America/Monterrey timezone)
  Category:    adjustment
  Description: Balance reconciliation
  Account:     whichever account you selected
  Amount:      the computed delta
  Source:      web

You can delete it later like any other transaction if you figure out what the
real missing transactions were and want to log them properly.

CREDIT CARD RECONCILIATION
--------------------------
Works the same way for credit cards. Enter how much you currently owe on the
card. The app computes: starting owed + all charges - all payments = calculated
owed. The delta is inserted as an adjustment transaction on that card.

API CALL
--------
POST /api/budget  { action: "reconcile", account, actualBalance, date?, month? }

Response:
  { ok: true, delta: number, transaction?: BudgetTransaction }
  { ok: true, delta: 0, message: "Balance already matches" }   ← if no gap

--------------------------------------------------------------------------------
4h. SUBSCRIPTIONS
--------------------------------------------------------------------------------

A separate section lets you maintain a reference list of recurring charges.
These are NOT automatically added to your transactions — they are just a
reminder of what to expect each month.

Fields when adding a subscription:
  Name        — service name (e.g., "Netflix", "Spotify")
  Amount      — monthly charge
  Account     — which card/account it bills to
  Category    — for reference (e.g., "entertainment", "software")
  Billing Day — day of the month when it charges (1-31)

The subscription list shows all active subscriptions sorted by billing day,
so you can see which charges are coming up soon in the month.

Adding:   POST /api/budget { action: "add-sub", name, amount, account, category, billing_day }
Deleting: POST /api/budget { action: "delete-sub", id }


--------------------------------------------------------------------------------
4i. CATEGORY BREAKDOWN
--------------------------------------------------------------------------------

Two breakdown sections display spending patterns:

  BY EXPENSE CATEGORY — each category with total spent and % of total expenses
  BY INCOME CATEGORY  — each category with total received and % of total income

These are calculated from the transactions list and update in real time as
you add or delete transactions.

5. TELEGRAM INTEGRATION
================================================================================

You can log budget transactions directly from Telegram without opening the app.

PATTERN
-------
  BM: [sign]$[amount] @[category] [description] #[account]

  - BM:       — required prefix (Budget Message)
  - sign      — + for income, - for expense (optional; defaults to expense if omitted)
  - $amount   — number, supports commas (e.g., $1,500 or $300)
  - @category — required; category tag (no spaces; use underscore if needed)
  - description — optional; any text between @category and #account
  - #account  — required; one of the valid account names (case-insensitive)

EXAMPLES
--------
  BM: +$16000 @earnings Salary #ScotiabankDebit
    → Income of $16,000 to ScotiabankDebit, category: earnings, desc: "Salary"

  BM: -$300 @food Groceries #NUDebit
    → Expense of $300 from NUDebit, category: food, desc: "Groceries"

  BM: -$1500 @rent Apartment #ScotiabankDebit
    → Expense of $1,500 from ScotiabankDebit, category: rent, desc: "Apartment"

  BM: -$99 @software #AMEX
    → Expense of $99 from AMEX, category: software, no description

VALID ACCOUNTS (case-insensitive in Telegram)
---------------------------------------------
  ScotiabankDebit
  NUDebit
  NUCredit
  AMEX

BEHAVIOR
--------
- The bot uses today's date in America/Monterrey timezone
- On success, the bot replies with a formatted confirmation:
    ✅ Transaction logged!
    Amount: -$300.00
    Category: food
    Description: Groceries
    Account: NUDebit
    Date: 2026-03-23
- On error (invalid account, missing @category, missing #account), the bot
  replies with an error message explaining what went wrong
- Transactions via Telegram appear in the web UI with source="telegram"

TELEGRAM /budget COMMAND
------------------------
Send `/budget` to the bot and it replies with the current month's cashflow
summary (income, expenses, net flow) — same as the summary cards on the web page.

6. API REFERENCE
================================================================================

All endpoints are at: /api/budget

GET /api/budget?month=YYYY-MM
  Returns full budget data for the month including:
  - transactions[]
  - savings[] (starting balances)
  - subscriptions[]
  - summary { totalIncome, totalExpenses, netFlow, cashNetFlow, byAccount, byCategory }
  - creditCards[] (utilization data per credit card)
  - totalSavings

GET /api/budget?config=1&month=YYYY-MM
  Returns only the savings config (starting balances) for the Setup page.

POST /api/budget — Actions:

  add-transaction
    Body: { action, amount, category, description, account, date, source }
    Creates a new transaction row in budget_transactions.

  set-savings
    Body: { action, account, amount, month }
    Upserts starting balance for one account in budget_monthly_savings.

  set-initial
    Body: { action, pin, month, balances: { [account]: number } }
    PIN-protected bulk upsert for all accounts. Used by Setup page.

  delete
    Body: { action, id }
    Deletes transaction by ID from budget_transactions.

  reset
    Body: { action, month }
    Deletes ALL transactions and savings for the given month. Destructive.

  verify-pin
    Body: { action, pin }
    Returns { ok: true } if pin matches BUDGET_SETUP_PIN env var.

  add-sub
    Body: { action, name, amount, account, category, billing_day }
    Creates a new row in budget_subscriptions.

  delete-sub
    Body: { action, id }
    Deletes subscription by ID from budget_subscriptions.

  reconcile
    Body: { action, account, actualBalance, date?, month? }
    Computes delta between actual and tracked balance, inserts an adjustment
    transaction if the gap is >= $0.01. Returns delta and inserted transaction.
    If balance already matches, returns { delta: 0, message }.

7. DATABASE TABLES
================================================================================

budget_transactions
-------------------
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid()
  date            DATE NOT NULL
  amount          NUMERIC NOT NULL  (positive = income, negative = expense)
  category        TEXT NOT NULL
  description     TEXT
  account         TEXT NOT NULL  (one of the four valid accounts)
  source          TEXT  ('web' or 'telegram')
  raw             TEXT  (original Telegram message, if applicable)
  telegram_chat_id TEXT
  created_at      TIMESTAMPTZ DEFAULT now()

budget_monthly_savings
----------------------
  id      UUID PRIMARY KEY DEFAULT gen_random_uuid()
  month   TEXT NOT NULL  (format: YYYY-MM)
  account TEXT NOT NULL
  amount  NUMERIC NOT NULL  (starting balance for that account in that month)
  UNIQUE(month, account)

budget_subscriptions
--------------------
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid()
  name        TEXT NOT NULL
  amount      NUMERIC NOT NULL
  account     TEXT NOT NULL
  category    TEXT NOT NULL
  billing_day INT NOT NULL  (1-31, day of month it charges)
  active      BOOLEAN NOT NULL DEFAULT true
  created_at  TIMESTAMPTZ DEFAULT now()

9. ACCOUNTS REFERENCE
================================================================================

The app recognizes exactly four accounts. These names must be used exactly
(case-insensitive in Telegram, exact match in the web form dropdown):

  ScotiabankDebit  — Debit/checking. Treated as cash. Included in Cash Net and Savings.
  NUDebit          — Nu debit card. Treated as cash. Included in Cash Net and Savings.
  AMEX             — American Express credit card. Has limit and cut date.
  NUCredit         — Nu credit card. Has limit and cut date.

To add or rename accounts, you must:
1. Update the ACCOUNTS constant in src/lib/api.ts
2. Update the VALID_ACCOUNTS array in api/telegram/webhook.ts
3. Update the CREDIT_CARDS config in api/budget/index.ts (if it's a credit card)
4. Update any hardcoded references in BudgetPage.tsx

10. FULL SETUP WALKTHROUGH (NEW MONTH)
================================================================================

Follow these steps on the 16th of each month (fiscal month start):

STEP 1 — Check your real account balances
  Open your banking apps and note down:
  - Scotiabank debit: actual balance
  - Nu debit: actual balance
  - AMEX: current outstanding balance (what you owe right now)
  - NUCredit: current outstanding balance (what you owe right now)

STEP 2 — Open /budget/setup
  Navigate to the setup page in the app.

STEP 3 — Enter your PIN
  Type the BUDGET_SETUP_PIN value and confirm.

STEP 4 — Enter starting balances
  Fill in the four fields with the values from Step 1.
  Click "Save Configuration".
  The system will confirm the data was saved for the current month.

STEP 5 — Go to /budget
  The main page now shows your starting balances in the Account Balances section
  with $0 income and expenses (no transactions yet for the month).

STEP 6 — Start logging transactions
  Via web form: use the Add Transaction form on the main page.
  Via Telegram: send BM: messages from your phone throughout the month.

STEP 7 — Monitor throughout the month
  Check /budget anytime to see:
  - How much you've earned and spent
  - Which categories are consuming the most
  - Credit card utilization and days until cut
  - Total savings projection

STEP 8 — Use /budget Telegram command for quick checks
  Send `/budget` to your bot to get a quick summary without opening the browser.

STEP 9 — At month end
  Review the final summary. Then repeat from Step 1 for the next month.
  Previous months remain accessible via the month navigation arrows.

11. MID-MONTH RECOVERY WORKFLOW
================================================================================

Use this when you're setting up after the 16th and already have untracked
expenses and balance changes on all your accounts.

THE SHORT VERSION
-----------------
Open /budget/setup, switch to "Mid-Month Catch-Up" mode, fill in the two-field
form for debit accounts and the single field for credit cards, click
"Save & Reconcile." Done — the app handles the rest automatically.

THE DETAILED VERSION
--------------------

WHAT YOU NEED BEFORE OPENING THE APP
  Check your banking apps and note down:
  - ScotiabankDebit: balance on the 16th (optional) + current balance
  - NUDebit: balance on the 16th (optional) + current balance
  - AMEX: current amount owed right now
  - NUCredit: current amount owed right now

  For debit accounts, the "16th balance" is ideally what the account showed
  before payday hit on the 16th. If you don't know it, just leave it blank.

STEP 1 — Open /budget/setup
  The page auto-detects you're mid-month and defaults to "Mid-Month Catch-Up."
  Enter your PIN.

STEP 2 — Fill in debit account fields
  For each debit account:
    Left field  (16th balance): enter what the account showed on the 16th,
                                OR leave blank if you don't know/don't care.
    Right field (right now):    enter what the banking app shows at this moment.

  The page shows a live preview of the adjustment amount for each account:
    Example — ScotiabankDebit: 16th=$20,000, now=$17,400 → adjustment -$2,600

  If you only fill the "right now" field: that balance becomes day zero.
  The 16th–today gap is simply not represented. Tracking starts from today.

STEP 3 — Fill in credit card fields
  For each credit card, enter the current amount owed (one field).
  This becomes the baseline. Future charges track on top from today.
  The charges between the 16th and today are absorbed into this number —
  they won't appear as line items, but the running total stays accurate.

STEP 4 — Click "Save & Reconcile"
  The page:
    1. Saves the 16th balance as the starting balance for each debit account
    2. Saves the current owed as the starting balance for each credit card
    3. For any debit account where you filled both fields, calls reconcile
       and inserts an adjustment transaction covering the gap
  The confirmation screen shows exactly which accounts were set and what
  adjustment amounts were created.

STEP 5 — Verify on /budget
  Click "Go to Budget →" in the confirmation.
  Account Balances should now match what your banking apps show.
  Adjustment transactions appear in the transaction list labeled
  "adjustment / Balance reconciliation."

STEP 6 — Continue normally
  Log new transactions via Telegram (BM:) or the web form.
  The system is now accurate from this moment forward.

OPTIONAL — Backfill specific transactions you remember
  If you recall a particular large expense (e.g., rent, a grocery trip), you
  can log it with the correct past date using the Add Transaction form on /budget.
  Then use Reconcile Balance on /budget to re-sync the running total back to
  reality. Or delete the old adjustment entry and let the real transactions
  replace its effect.

  Use the web form for past dates — the Telegram BM: parser always uses today.

NOTE: Adjustment transactions appear in the category breakdown under
"adjustment." They won't pollute your @food or @transport categories. If you
later itemize the missing transactions properly, delete the adjustment entry
first so the numbers don't double-count.
